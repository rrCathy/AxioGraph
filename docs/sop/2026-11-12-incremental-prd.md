# AxioGraph 增量 PRD（2026-11-12）

> 本文档只描述本轮变更，不重写全量 PRD。撰写前已核对代码与实库，与任务摘要不一致处见文末「附录：核对结论」。

---

## 0. 项目信息

- **Language**：中文
- **Programming Language**：沿用现状（FastAPI + SQLite + React/TS/Vite + Cytoscape + TipTap + zustand），不引入新依赖
- **Project Name**：`axiograph`
- **原始需求复述**：用户提出 5 条诉求——① 前端完整展示一页文档；② 识别书的结构并提取书名/作者/目录（目录可快速组织图谱）；③ 删除旧的伽罗瓦理论信息；④ 提高扫描件文字提取能力；⑤ AI 自动提取关键信息组织图谱、增加节点，交用户确认。

---

## 1. 产品目标

让 AxioGraph 从"能对一页做校勘"进化为"能以书为单位高效建档"：完整清晰的整页阅读体验 + 自动化的书籍结构（书名/作者/目录）识别与扫描件文字提取 + 半自动的连续候选提取，同时把旧伽罗瓦数据与死代码彻底清场——**人始终在确认环上**，所有自动产出必须经用户确认才入图谱。

## 2. 用户故事（含验收口径）

### US-1 整页完整浏览（需求 1）

> As a 校勘者, I want 在工作台左侧完整浏览一页文档（滚动 + 缩放），so that 我能看清整页版面与全部内容，再决定引用哪一段。

**验收口径**（可测）：
- [ ] 对任意上传的 PDF 页，查看器可完整渲染整页内容，无截断、无裁切（含超长/超大开本页面）。
- [ ] 提供三种缩放档位：适应宽度、适应整页、100%，切换后重渲染 < 1s（本地渲染，无网络）。
- [ ] 支持连续滚动浏览单页内的全部内容（不是只显示首屏）。
- [ ] 现有 bbox 编号反跳交互保留：点击文本层编号 → 查看器滚动并高亮对应 bbox 区域；反向（选区 → 编号）不受影响。
- [ ] 深色/浅色主题下均正常显示，颜色全部走 `var(--ag-*)`。

### US-2 书籍结构识别（需求 2）

> As a 建档者, I want 系统自动识别书名、作者、目录，so that 我不用手工录入元数据，且能用目录快速组织章节级图谱节点并按章节跳页。

**验收口径**：
- [ ] **书签来源**：PDF 有内嵌书签时，用 PyMuPDF `get_toc()` 解析，目录条目 100% 生成（跳级/缺页码条目要容错）。
- [ ] **无书签**：在前 20 页内自动判定目录页（文本层或 OCR 命中"目录 / Contents / CONTENTS"），对目录页调用视觉模型解析出"章节标题 + 书页码"。
- [ ] **页码偏移**：检测"书页码 → PDF 页序号"的偏移量（用已提取页文本/视觉模型交叉验证至少 1 个锚点条目），偏移量展示给用户，可手动修正。
- [ ] **书名/作者**：从封面页与版权页提取（文本层优先，扫描页走视觉模型），允许用户编辑。
- [ ] **人工兜底**：目录页定位失败或解析质量差时，允许用户手动指定目录页码范围，并逐条补录/编辑目录条目。
- [ ] **目录确认**：所有目录条目在可编辑表格中确认后，方可：① 作为章节结构节点写入图谱（标记来源）；② 工作台出现章节列表，点击章节 → 跳转到对应 PDF 页窗口。
- [ ] 结构识别产生的中间数据可重跑覆盖（书改了目录识别结果，重跑不产生重复节点）。

### US-3 清除伽罗瓦旧数据与死代码（需求 3）

> As a 测试者, I want 把伽罗瓦理论相关的旧数据和停用的批处理代码全部清掉，so that 测试不被旧数据干扰、代码库不再有误导性的死路径。

**验收口径**：
- [ ] **备份先行**：删除操作前自动生成 `data/axiograph.db` 的时间戳备份（如 `axiograph.db.bak-20261112-prepurge`），备份文件不参与运行。
- [ ] **数据清除范围（仅伽罗瓦）**：books 表中 `伽罗瓦理论-章璞` 记录（级联 chapters/pages/candidates/graph_nodes/graph_edges）；与该书关联的 legacy 节点 320 条、legacy 边 342 条随级联清除；`data/lightrag/` 下该书旧导出目录删除。**`简明复分析` 的页数据、confirmed 节点、candidates 必须完好无损；`代数拓扑` 记录保留。**
- [ ] `data/books/` 下 37 个 PDF 源文件一个不删（用户资料）。
- [ ] `data/axiograph.db.bak`、`data/axiograph.db.before-fix-20261111` 两个既有备份文件保留不动。
- [ ] **死代码物理删除**：`backend/parser.py`、`backend/extractor.py` 删除；`books.py` 中旧批处理端点（`/{book_id}/pause`、`/resume`、`/cancel` 及 parse_pdf/extract_from_chapters/save_nodes_and_edges 相关逻辑）移除，`/upload`、列表、详情、删除端点保留；`graph_store.py` 中仅被旧链路使用的函数（如 `save_nodes_and_edges`）删除，被活链路引用的函数（`get_graph_for_book`、`get_node_detail`、`update_node`、`delete_node`、`search_nodes`、`get_context_for_qa`、`sync_book_counts`）保留或迁入活链路模块；`lightrag_bridge.py` 从启动路径（`main.py` on_startup/shutdown）与 chat 问答回退中摘除后删除，`data/lightrag` 相关配置同步清理。
- [ ] 删除后 `python scripts/smoke.py` 11 项验收全部通过；`/docs`（OpenAPI）中不再出现已删端点；前后端无 import 残留（`npm run build` + `tsc --noEmit` 通过）。

### US-4 扫描件文字提取增强（需求 4）

> As a 校勘者, I want 扫描页也能自动提取出高质量文字，so that 我少做人工手输，快页快校。

**验收口径**：
- [ ] 从 FreeLLMAPI 在线视觉模型中实测择优 2-3 个真实扫描页确定主力模型（候选：nemotron-parse-2.0、glm-4.6v-flash、llama-3.2-90b-vision、moondream-3.1-9b-a2b、llava-1.5-7b），选型结论与实测对比记入代码注释或 docs。
- [ ] 视觉提取入口接入现有两阶段流程：视觉模型输出 → 置信度评估 → 低于阈值（沿用 <55 口径）转人工手输，页状态沿用 `bad_page` 语义。
- [ ] 实测指标：对同一批扫描页，视觉模型提取的 `char_count` 与人工校对文本的重合度显著优于现 tesseract.js 结果；`bad_page` 页占比下降。
- [ ] 失败兜底：视觉模型调用失败（超时 180s / 网络异常 / 返回空）→ 自动回退人工手输路径，不阻塞页面流程。
- [ ] 零新依赖：不安装 RapidOCR / 新版 tesseract 等任何新包；LLM 客户端沿用 `trust_env=False`。
- [ ] 视觉提取结果仍写入 `pages.text_raw` 并进入现有校勘流程（text_corrected、quality 字段复用），不改存储结构。

### US-5 自动模式连续提取（需求 5）

> As a 建档者, I want AI 按章节/页序范围连续逐窗自动提取候选节点，产出待确认队列由我统一确认，so that 一本书的建档从"逐窗手动点"变成"启动→审阅确认"。

**验收口径**：
- [ ] 在工作台候选确认流上新增"自动模式"：用户设定起止范围（按章节选择，或按页序 1-N），系统沿用现有 1-3 页窗口机制连续逐窗调 LLM，产出全部为 `pending` 状态 candidates，**不自动写图谱**。
- [ ] 串行请求：同一时刻只有 1 个 LLM 请求在跑（本地服务慢，不并发）。
- [ ] 可暂停 / 停止 / 恢复：停止复用 `/api/tasks/{task_id}/cancel` 协作式取消语义；进度展示沿用现有长任务计时器（无假百分比，显示"第 X 窗 / 共约 Y 窗"即可）。
- [ ] 容错：单窗失败自动重试 1 次，仍失败则标记该窗口"需人工处理"并继续下一窗，不阻塞整本。
- [ ] 自动模式产出的候选进入现有确认流（确认/驳回/合并/undo 全部可用），与手动提取的候选无差别。
- [ ] 中断后可续跑：从最后完成的窗口之后继续，不重复生成已完成窗口的候选。

### 后端接口新增（供架构师参考，非 UI）

- 清除：一次性数据迁移脚本（含自动备份），不暴露为常驻 API

## 附录：核对结论（供架构师，摘要 vs 实际）

1. **实际数据库在 `data/axiograph.db`**（`config.py` 用 `data_dir / "axiograph.db"`）；`backend/axiograph.db` 是一个**无任何业务表的空壳文件**，建议本轮顺手删除或移出仓库（默认：删除，不属用户资料）。
2. **库里有 3 本书**，不止伽罗瓦：`伽罗瓦理论-章璞`（legacy 320 节点 / 342 边归它）、`简明复分析`（418 extracted 页 + 15 bad_page + 1 confirmed 节点 + 3 candidates，**是活数据必须保**）、`代数拓扑`（ready，空壳记录）。**删除范围必须按 book_id 精确圈定，不能按 review_status='legacy' 全删了事再级联误伤。**
3. **`graph_store.py` 不是死代码**：被 `routers/graph.py`（图谱展示）、`routers/chat.py`（QA 上下文）、`routers/workbench.py`（sync_book_counts）引用，删除必须做函数级手术。
4. **`lightrag_bridge.py` 仍在运行路径**：`main.py` on_startup/on_shutdown 初始化、`chat.py` 两处回退查询、`books.py` ingest/delete_book。摘除需动 3 个文件。
5. **`parser.py` / `extractor.py` 只被 `books.py` 旧批处理逻辑引用**，可整文件删；`books.py` 需同步删除 `/{book_id}/pause|resume|cancel` 等旧批处理端点（`/upload`、列表、详情、`DELETE /{book_id}` 保留）。
6. **schema 已具备本轮所需字段**：`candidates` 有 `page_start/page_end/quote/relations_json`，`graph_nodes` 有 `page_start/page_end/review_status/source_quote/created_by/merged_into`，`pages` 有 `blocks_json/quality/ocr_confidence/status`——需求 2/5 主要新增 `chapters` 复用扩展或新表（如 `book_structure`），无破坏性迁移。
7. 前端工作台组件实际为 `Workbench.tsx` + `workbench/WorkbenchPanels.tsx`，`frontend/src/stores/` 仅 `appStore.ts`——自动模式状态并入该 store。
